# 확장 구현 계획

## 목적과 범위
기존 6개 메뉴, 박물관형 화면, 기록 ID·주소, 원본 28개 파일과 기기 보관 데이터를 보존하면서 확장 기획 26항목을 구현한다. 공개 콘텐츠의 사람 검수·기관 동의·번역 승인·상용 결제와 AI 계정은 실제 증거가 있어야 완료로 기록한다.

## 컴포넌트와 데이터 흐름
- 지식 계약: 사건·자료·판본·번역·디지털 재현·인물·장소·근거·권리·관계, 공개 데이터 검증.
- 웹: 현행 탐색에 근거/자료/인물·장소 상세 연결, 연구 작업공간, 계정 선택, 교사용 도구, 정정 접수, 비공개 편집 UI.
- API: Node HTTP/SQLite 모듈형 서버, 인증·권한·검수·개인/공동 작업·제보·기관·주문·감사.
- 작업 실행기: 승인 버전의 공개 export, 재시도 가능한 외부 알림·자료 작업, 비용/실패 관측.
- 모바일: 공개 목록/상세/선택 다운로드와 호환 캐시, 갱신·보류 안내.
- 배포: 공개 정적 호스팅과 보호된 운영 API 분리, 지속 저장·백업·헬스 체크·복구.

비공개 입력 → 서버 검증·소유권 검사 → DB 트랜잭션/버전 저장 → 실제 검수자 승인 → 승인 버전만 export → 공개 빌드·해시 → 웹/앱. 개인 메모·제보자 정보·초안·계약은 공개 export에 포함하지 않는다.

## 구현 순서
1. 공통 지식·작업 계약과 DB 마이그레이션/권한 경계.
2. 도메인·저장소·API와 독립적인 웹 연구·교육 기능을 병렬 구현.
3. 공개 기록/검색/연표/홈/모바일에 연결하고 실제 인증·편집·제보·공동 작업 통합.
4. 설정된 공급자만 사용하는 결제·AI·알림 어댑터, 운영/배포/복구 문서.
5. 타입·린트·도메인/DB/API·브라우저·정적 산출물·모바일 번들 검증.

## 위험과 보호
- 기존 미커밋 변경은 보존한다. 원본 자료와 운영 DB 초기화 금지.
- 사람 승인이나 번역/기관 협력을 자동 생성하지 않는다. 외부 설정이 없으면 기능을 비활성 상태로 설명한다.
- 개인 데이터는 소유권, 공동 작업은 역할, 편집은 검수/발행 정책을 서버에서 검증한다.
- 충돌 시 강제 덮어쓰지 않고 이전 버전/내보내기·명시적 병합을 제공한다.
- 공개 피드 호환 버전은 유지하면서 분할 계약을 추가한다.
- 실제 기관·전문가 검수, 실기기/보조기기, 공급자 sandbox, 클라우드 배포는 환경 확보 후 별도 검증한다.

## 검증과 롤백
단위 검사: 계약/날짜/근거/권리/상태 전이/병합. DB/API 통합 검사: 지속 저장, CSRF, 다른 계정 거절, 역할, 승인 무효화, 비공개 제외, 중복 이벤트. 브라우저: 로컬 연구·학습, 계정과 실제 제보/CMS, 작은 화면, 기존 흐름 유지. root lint/typecheck/test/build와 static/Playwright/Android export를 실행한다.

추가 마이그레이션은 이미 적용된 파일을 수정하지 않는다. API 전환 전 DB 온라인 백업, 복구본 검증을 수행한다. 공개 웹은 이전 승인 릴리스로 복귀할 수 있고, 기존 로컬 보관 키는 유지한다. API 기능을 비활성화해도 공개 읽기는 유지하며 데이터 삭제를 롤백 수단으로 사용하지 않는다.
