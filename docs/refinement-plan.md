# 확장 버전 고도화 구현 계획

2026-10-07 사용자가 승인한 30개 기획 항목을 구현한다. 기존 주요 메뉴 6개, 홈 카드 4개, 박물관 디자인, 수집 원본 28개, 자료 ID와 공개 URL, 기존 기기 저장 키를 유지한다. 기존 미커밋 작업을 되돌리지 않는다.

## 데이터 흐름

입력 → 검증된 기기 복구 초안 → 사용자가 선택한 기기 작업 저장 → 명시적인 계정 공유 → 서버 소유권/역할 및 버전 검증 → 새 버전 저장. 초안 저장 실패를 완료로 표시하지 않는다. 서로 다른 초안과 서버 버전은 사용자가 보존 방법을 선택하기 전 덮어쓰지 않는다.

편집 → 자료/근거/권리 사전 검사와 영향 목록 → 불변 버전 검수 → 작성자와 다른 검수자의 승인 → 서명된 export → 빌드 → 배포 및 공개 URL/모바일 산출물 확인. 각 단계의 증거를 분리하고 정정 완료는 실제 반영 버전·배포 확인 증거·명시적인 종결 근거를 모두 연결한다.

주문 결제 확인 → 계약/이행 작업 → 고객 확인. 공급자의 응답과 실제 전달 증거를 구분한다. 공개 AI, 전체 번역, 좌표, 미디어는 실제 공급자·검수·권리 증거가 있을 때만 제공한다.

## 구현 순서

1. 기기 복구, 로그인 복귀, 삭제 범위와 충돌 보호를 먼저 구현한다.
2. 검색·자료·연구·교육과 일반 폼 기반 협업을 병렬로 구현한다.
3. 기존 API에 하위 호환적인 운영 계약과 추가 마이그레이션을 적용한다. 이미 적용된 001–006 마이그레이션은 수정하지 않는다.
4. CMS·운영 큐·권리·정정·발행 확인과 실제 API를 연결한다.
5. 모바일·번역 계약·외부 서비스와 운영 문서를 연결하고 항목별 증거를 기록한다.
6. 린트·타입 검사·단위/통합·프로덕션 빌드·정적 경로·브라우저 핵심 흐름을 실행한다.

## 주요 위험과 보호

- 기기 입력과 서버 데이터를 변경하므로 기존 키를 유지하고 새 복구 키는 별도로 둔다. 손상 원본은 다운로드할 수 있게 유지하며 자동 덮어쓰지 않는다. 삭제는 사용자가 선택한 이 서비스의 키만 대상으로 한다.
- 운영 DB가 존재한다고 가정한다. 새 컬럼/테이블은 추가 마이그레이션으로 만들고 기존 데이터의 동작과 권한을 유지한다. 계정 권한과 민감 작업은 서버에서 재검증한다.
- 로그인 복귀 URL은 같은 사이트 내부 경로만 허용한다. 인증 토큰을 기기 저장소에 추가하지 않는다.
- 실제 배포 확인, 기관 이용 허가, 전문 검수, 공급자 전달, 실제 기기 검증과 사용자 연구를 테스트 결과로 대체하지 않는다. 관련 기능과 검증 경로를 구현하되 외부 증거가 없는 항목은 미검증으로 남긴다.
- 새 역사 사실·외국어 번역·좌표·기관 계약·가격을 임의로 운영 데이터에 작성하지 않는다.

## 검증과 완료 증거

30개 항목별 구현 파일, 실행 경로, 자동 검증, 외부 출시 조건을 별도 매핑한다. 초안 작성 후 이동/재시작 복구, 잘못된 복귀 URL, 손상 저장, 충돌 버전 보존, 협업 권한, 교육 재사용/비공개 교사 메모, 제출 버전 피드백, CMS 독립 승인, 배포 단계 증거, 정정 종결, 결제/환불 미확정, 최신 보류 상태 복구를 주요 검증 대상으로 한다.

## 배포와 롤백

배포 전에 온라인 DB와 비공개 파일 bundle을 새 위치에 백업한다. 새 API/worker를 먼저 배포하고 추가 계약을 사용하는 UI를 다음에 배포한다. 데이터 삭제나 이전 마이그레이션 수정 없이 이전 UI와 호환되는 추가 구조를 우선한다. 새 증거·보안 정책을 읽지 못하는 이전 API로 직접 되돌리지 않는다. 복구는 원본을 덮어쓰지 않는 별도 경로에서 검증한다. 보류/삭제/역할 취소 원장은 최신 상태를 대조한 뒤 공개 산출물을 재생성한다. 커밋·push·실제 호스팅 배포는 이번 요청에 포함되지 않는다.
