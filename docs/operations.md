# 편집·검수·발행 운영

## 상태와 책임

| 상태 | 의미 | 공개 |
| --- | --- | --- |
| needs-review | 수집 또는 편집되었으나 관련성·사실·출처 검토가 필요함 | 제외 |
| source-checked | 등록 원문과 서지·본문 근거를 대조함. 사람의 최종 승인과 다름 | 조건 검증 후 허용 |
| approved | 지정 검수자가 실제로 검수했고 humanReviewed가 true임 | 조건 검증 후 허용 |
| withheld | 무관함·오류·권리·검수 문제로 공개를 보류함 | 제외 |

공개 여부는 점수가 아니라 자료 상태와 근거 연결로 판단합니다. 자동화는 사람의 승인 이력을 발명하지 않습니다. 초기 편집 기록의 source-checked 상태는 인적 검수 완료라는 뜻이 아닙니다.

## 일상 절차

1. 비공개 수집 환경에서 원문, 작성자, 기관, 작성 시기, 자료 위치, 사용권, 중복 여부를 확인합니다.
2. `npm run content:audit`로 기존 수집 자료의 관련성·링크 상태를 점검합니다. 원본은 보존합니다.
3. 공개 가능한 편집본만 editorial.json의 명시적 데이터 계약으로 작성합니다. 문단·연표마다 sourceIds를 연결합니다.
4. `npm run content:review -- --id RECORD_ID`로 출처·한계·검수 상태·근거 연결을 검토합니다.
5. 연도 미확인은 unknown, 추정은 approximate로 기록합니다. 자료 작성일과 사건 발생일을 구분합니다.
6. 여러 URL이 같은 자료에서 파생되면 같은 independenceGroup을 부여합니다. 출처 수를 독립 검증 수처럼 제시하지 않습니다.
7. `npm run content:gate`, lint/typecheck/test/build/test:static/test:browser 후 정적 미리보기를 확인합니다.
8. 검수자가 PR의 콘텐츠 체크리스트를 검토합니다. 공개 저장소의 모든 브랜치·PR에는 비공개 초안을 넣지 않습니다.
9. 승인 후 main에 병합하면 Vercel 배포와 release SHA 확인이 실행됩니다.
10. 출처 변경·정정 요청은 운영자가 검토하고 corrections/updatedAt/review.note에 수정 이유를 남깁니다.

## 실제 운영 도구

- `content:review`: 상태별 큐와 기록별 검수 자료를 표시하는 읽기 전용 CLI
- `content:gate`: 편집 스키마를 검증하며 인적 검수를 대신하지 않음
- `content:audit`: 원본 수집 자료를 평가해 audit-report.json 생성
- `content:links`: 승인 호스트만 HTTPS로 점검하고 링크 보고서를 생성
- `preview`: 정적 웹을 loopback 주소에서 미리보기
- PR 템플릿: 관련성, 출처, 독립성, 사실·해석, 인적 승인, 개인정보, 복구 확인
- PR CI: 코드·콘텐츠·웹 접근성·모바일 번들의 반복 검증

링크 검사에는 타임아웃, 제한된 리다이렉트, 승인 호스트, DNS 공개 주소 확인과 검사 시점 IP 고정이 적용됩니다. HEAD 거절·시간초과는 원문이 없다는 확정 증거가 아닙니다. reachable도 주장 사실이나 사용권을 검증한 결과가 아닙니다.

HEAD 405/501에는 같은 정책의 제한된 GET을 사용하고 응답 본문을 취소합니다. 현재 등록된 연결 자료 주소 8개는 운영 검사 실행 시 모두 reachable이었으며 이후 상태 변화는 주간 링크 보고서로 확인합니다. 원문과 현대 기관 해설의 구분은 각 자료의 유형을 따릅니다.

## KPI와 검토 주기

주간에는 검색 결과 없음, 상세 이동, 원문 열람, 관련 기록 이동, 링크 점검, 검수 대기량을 검토합니다. 월간에는 Search Console 색인·검색 클릭·CTR, 정정·반려 이유, 사용자가 실제로 기록을 찾는 시간과 모바일 이용 흐름을 검토합니다. 기록 수만 발행 목표로 삼지 않습니다.

현재 브라우저 행동 집계는 기기 내부 데이터이며 서비스 전체 KPI가 아닙니다. 외부 분석 계정·수집 동의·보관 정책을 연결하지 않은 상태에서 전체 이용률을 계산했다고 보고하지 않습니다.

## 정정과 복구

기존 자료를 지우지 않고 공개 편집 기록의 상태를 변경하거나 정정 내용을 추가합니다. 공개가 보류된 기록은 새 빌드에서 노출되지 않습니다. 이미 다운로드된 오프라인 보관본과 제3자 캐시는 원격으로 회수할 수 없습니다. 민감한 자료는 발행 전 판단이 필요합니다.

인적 승인·비공개 관리자 인증·사용자 제보는 정적 웹과 분리한 API로 구현했습니다. 실행·역할·마이그레이션·서명 발행·백업은 [서버 운영](backend-operations.md), 외부 출시 조건은 [서비스 경계](service-boundaries.md)를 따릅니다. 파일/PR 검수와 실제 CMS의 인적 승인을 혼동하지 않습니다.
