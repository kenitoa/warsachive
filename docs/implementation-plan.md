# 아카이브 고도화 실행 계획

## 목적과 유지할 계약

다크 박물관 디자인, 좌측 탐색, 여섯 개 메뉴, 기존 기록 URL, JSON 발행과 Vercel 정적 배포를 유지한다. 자료 찾기 → 맥락 이해 → 근거 확인 → 다음 읽기 흐름을 완성한다. 원본 수집 파일을 삭제하거나 운영 데이터베이스를 초기화하지 않는다.

## 영향받는 구성과 데이터 흐름

- 콘텐츠: 원본 JSON + 별도 편집 정보 → 런타임 스키마 검증 → 공개/검토 대상 구분 → 검색용 최소 데이터, 상세 페이지, 편집 페이지.
- 웹: 홈, 검색, 상세, 주제, 연표, 컬렉션, 스토리, 소개와 공통 탐색. 기기 내 보관함·메모·읽기 설정·비교·인용·정정 안내를 연결한다.
- 운영: 출처/내용 감사 보고, 검수 상태와 변경 이력, 발행 검사, PR 검사, 배포 버전 및 배포 후 확인.
- 모바일: 정적 공개 자료 목록/상세/검색/보관함을 같은 계약으로 연결한다.

## 구현 순서

1. 콘텐츠 계약, 검토 상태, 외부 근거 대조와 원본 보존. 검토되지 않은 기존 주소는 안내 페이지로 유지하고 잘못 연결된 본문을 재노출하지 않는다.
2. 검색 조건 URL 보존, 세분화 필터, 상세 근거/인용/복귀, 브라우저 저장과 읽기 도구.
3. 질문 중심 주제, 실제 시점 연표, 독립 컬렉션/스토리/학습 경로, 소개 정책.
4. SEO·공유·RSS·검색 인덱스·성능, 검수 도구·CI·배포 smoke, 모바일 연동.
5. 전체 타입·린트·테스트·빌드와 브라우저 사용자 흐름 확인, 요구사항 추적 문서 갱신.

## 위험과 대응

- 자동 점수는 사실의 정확성이나 사람의 승인을 보증하지 않는다. 출처 대조와 사람 검수 상태를 구분하고 자동으로 사람 검수 완료를 부여하지 않는다.
- 원본 28건은 보존한다. 공개 추천·검색과 기존 주소 안내를 분리해 오류 확산과 주소 단절을 방지한다.
- 공개 정적 호스팅에 비공개 초안, 운영 자격증명, 쓰기 권한을 넣지 않는다.
- 기기 내 저장의 장애·손상·다른 탭 변경을 처리한다. 사용자 메모와 검색어 원문을 원격 분석에 보내지 않는다.
- 계정 동기화, 여러 편집자 동시 편집, 서버 접수, AI 질의응답은 별도 서비스와 권한/비용/보관 책임이 필요하다. 화면의 가짜 완료 동작을 만들지 않고 의존 조건과 연결 계약을 문서화한다.

## 검증과 출시 기준

- npm run lint/typecheck/test/build, git diff --check.
- 잘못된 JSON/출처/중복/편집 상태 차단, 미검수 콘텐츠 비공개, 원본/기존 URL 보존.
- 검색 → 상세 → 원문 → 검색 복귀, 필터 공유, 보관함/메모/비교/인용, 저장 장애.
- 모바일 폭, 키보드, 확대, 포커스와 대비; 자동 검사와 실제 보조기기 검증을 구분해 보고.
- 모든 섹션 canonical/사이트맵/피드/자산이 최종 basePath에서 맞고 배포 SHA가 확인됨.

## 롤백

기존 원본과 ID를 유지하며 새 편집 레이어/승인 콘텐츠 버전을 이전 버전으로 복원한다. 승인된 과거 커밋의 정적 산출물을 재배포한다. 사용자 브라우저 저장 데이터는 버전 변환으로 보존하며 롤백을 위해 초기화하지 않는다. 실제 운영 배포·외부 계정 권한이 필요한 확인은 별도 미검증 항목으로 기록한다.
