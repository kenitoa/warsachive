## 새 실행 경로

`start.cmd` 또는 `npm run start`는 API(4200), 별도 worker, 웹(3000)을 실행하고 상태를 확인한 뒤 브라우저를 연다. 서버가 만들어진 것과 최초 관리자가 생성된 것은 별개이며 운영용 계정이나 가짜 데이터는 자동 생성하지 않는다. 최초 관리자 생성은 `npm run admin:create -- <email> <name>`로 수행하며 비밀번호는 일시적 환경 변수 또는 stdin으로 전달한다. 명령 인수에 비밀번호를 넣지 않는다.

로컬 시작기는 현재 공개 자료 중 출처 대조 상태인 자료를 계정 생성 없이 안전하게 수입한다. CMS 게시물과 보류 기록을 덮어쓰지 않는다. 별도 운영 환경에서는 신뢰하는 출처 대조 전용 snapshot을 `ARCHIVE_API_STATIC_IMPORT_FILE`에 지정하거나 실제 관리자가 `npm run content:import -- <absolute-snapshot-path>`로 수입한다. 정적 자료 수입은 기존 출처 확인 상태를 유지하고 사람 승인으로 바꾸지 않는다. CMS의 새 게시물은 실제 작성자와 다른 검수자가 승인해야 한다.

## 승인 자료를 정적 발행에 반영

1. API 운영 환경에 별도 `ARCHIVE_PUBLICATION_SECRET`을 설정한다. 세션 키와 분리하고 32자 이상을 사용한다.
2. 작성·대조·독립 승인·발행 후 worker가 `<ARCHIVE_API_EXPORT_DIR>/approved.json`을 생성한다. private notes는 제외하며 승인 증거와 보류 ID를 서명한다.
3. 신뢰하는 빌드 머신에 파일을 전달하고 `ARCHIVE_APPROVED_EXPORT_FILE`에 절대 경로, `ARCHIVE_PUBLICATION_VERIFY_SECRET`에 검증 키를 설정한다. API 관리자 URL이나 키를 공개 브라우저에 넣지 않는다.
4. `npm run content:gate`, `npm run build`, `npm run test:static`으로 검증한다. 변조·잘못된 승인·겹치는 공개/보류 ID는 빌드 실패다.
5. 보류된 자료는 검색·지식 관계·관련 컬렉션·모바일 다운로드 산출물에서 제외하고 기존 상세 주소에는 보류 안내를 남긴다. 이전 배포나 기기 보관본은 소급 삭제할 수 없으므로 갱신 시 상태를 알린다.

승인 파일 전송과 실제 호스팅 배포는 운영자의 저장소·빌드·클라우드 권한이 필요하다. 이 세션에서 외부 계정에 업로드하거나 실제 운영 승인을 만들지 않았다.

## 제품·운영 지표

독자 흐름은 목적별 진입→기록→출처→저장/인용/학습 경로로 평가한다. 현 검색 평가 세트는 한국어 제목·영문 authority 별칭·빈 결과를 다룬다. 확대 시 정답 자료와 부적절한 노출, stale 번역과 권리 보류를 회귀 세트로 추가한다. 운영은 오류율·지연·큐 적체·로그인 실패·주문/환불 미확정 상태를 추적한다. 비공개 질문·메모를 기본 분석 데이터로 수집하지 않는다.

기관별 실제 자료/교육 제공 비용, 공급자 비용, 수동 검수 시간을 비용 기준선으로 기록한 뒤 유료 상품을 설정한다. 근거 없는 가격이나 계약, 매출·전환율·학습 효과를 예시 값으로 운영 데이터에 넣지 않는다. 서비스 약관·환불 정책·개인정보 보관 기간과 실제 공급자 점검이 완료되기 전 live 결제는 켜지 않는다.
